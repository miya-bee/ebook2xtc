# 13. AVD環境と設定の持ち運び

環境プロファイルを使うと、別のPCに同じAVDの基本設定を作れます。自分のAVDからも「その他」タブの「AVD環境の移行」でJSONを書き出せます。

> 🔑 **ログイン情報や書籍は移りません**: Google／リーダーアプリのログイン情報、リーダーアプリの書籍・ダウンロードデータ、AVDのユーザーデータ・キャッシュ・スナップショットは、環境プロファイルに含まれません。ログイン済みの状態そのものは移行しません。

## 配布版に同梱の環境プロファイルで始める

配布版には `ebook2xtc-S4Capture_API35_Play-environment.json` を `ebook2xtc.exe` と同じフォルダーに同梱します。初回起動時にアプリが自動検出し、「取得」タブ上部の「Android環境の準備」からAVDを作成します。Android Studioの入手・導入手順・準備の再確認・標準環境の設定を、この欄で順に操作できます。[2章](02-android-studio.md)の「Google Play対応のAVDを作る」の手作業は不要です。AVDのハードウェア設定（キーボード入力の有効化を含む）と、ebook2xtcの出力対象・倍率・表示密度が、まとめて設定されます。

**準備（初回だけ）**

1. [2章](02-android-studio.md)の「Android StudioとSDKを入れる」の手順1〜5を行います（Android Emulator、Platform-Tools、Command-line Tools、System Imageの導入と、準備の再確認）。仮想化の警告とPC再起動の扱いは、2章で説明しています。
2. ebook2xtcを起動し、「取得」タブ上部の初回セットアップ欄を確認します。同梱JSONとSDKを自動で調べ、必要なSystem Imageを画面に表示します。JSONを手で開く必要はありません。
3. System Imageが未導入と表示された場合は、Android Studioの「SDK Manager」→「SDK Platformsタブ」で右下の「Show Package Details」をオンにし、表示されたAndroidの版・種類・CPUの種類に合うもの（同梱版はAndroid 15/API 35、Google Play、x86_64）を入れます。完了後にアプリの「準備を再確認」を押します。導入済みでも見つからなければ、同じ欄の「SDK保存先を指定（認識しない場合）」でAndroid StudioのAndroid SDK Locationを選びます。「導入手順を開く」から本章を開けます。

**読み込む**

4. 「標準環境をセットアップ」を押します。ファイル選択やAVD名の入力は不要です。作成中は進捗表示が出ます。
5. 完了すると、作成したAVDが「取得」タブの③に選ばれ、⓪出力対象・②キャプチャ解像度に同梱JSONの値が反映されます。
{: start="4"}

同じ設定のAVDがすでにあれば作り直さずに再利用します。同名でも設定が異なる場合だけ、既存AVDを残して `（元の名前）_import2` などの別名で作成するかを確認します。AVDを自動起動したり、既存AVDを上書きしたりはしません。任意のJSONを手動で読み込む従来の機能は「その他」タブに残ります。

起動時に準備済みのAVDを検出すると、「Android環境の準備」は「環境準備済み」と表示され、操作ボタンは折りたたまれます。「導入・再設定を開く」を押すと、Android Studioの入手先・導入手順・準備の再確認を再び使えます。導入中に「準備を再確認」を押した場合は、準備が整っていても操作欄を開いたまま結果を表示します。

「準備を再確認」は、AVDと仮想化を確認する間「Android環境を確認しています…」と表示します。キャプチャまたは変換の実行中は、設定が変わらないよう再確認と標準環境のセットアップを開始できません。

**起動して仕上げる**

6. 仮想化の警告が出ているPCだけ、[2章の手順7](02-android-studio.md)に従ってWindowsの機能を有効にし、**Windows PC本体を一度再起動**します。警告がなければ再起動は不要です。その後「取得」タブの③で「起動」を押します（[5章](05-launch-avd.md)）。初回の起動はAndroidの初期設定を含むため、時間がかかります。
   仮想化診断が利用不可と表示しても、環境に合わない判定の可能性があるため、③の起動時に「このまま起動を試す」を選べます。起動できない場合は[2章](02-android-studio.md)の設定を確認してください。
7. 「その他」タブの「AVD環境の移行」にリーダーアプリの導入状態が表示されます。未導入ならPlayストアからリーダーアプリを入れ、「リーダーアプリ導入を確認」を押して再確認します。Androidとリーダーアプリの日本語化、Google／リーダーアプリのアカウントへのサインインを行います（[3章](03-japanese-and-reader.md)）。
8. Developer optionsの「Stay awake」など、画面スリープの設定を行います（[4章](04-keyboard-and-sleep.md)）。キーボード入力は、同梱プロファイルで有効になっています。
{: start="6"}

> 🔑 同梱のJSONには、ログイン情報や書籍、リーダーアプリそのものは入っていません。アカウントは利用者自身のものでサインインしてください。

同梱JSONは特定のリーダーアプリを指定していません。リーダーアプリ本体も含みません。読み込み先ではPlayストアからお使いのリーダーアプリをインストールして「取得」タブの「リーダーアプリ」欄で選び（[3章](03-japanese-and-reader.md)）、新しいAVDを起動後に「リーダーアプリ導入を確認」で実際の状態を確かめてください。

| 読み込むときの表示 | 対処 |
|---|---|
| 「必要なSystem Imageが未導入です: …」 | Android 15／Google Play／x86_64のイメージがInstalledか、SDK Managerの **Android SDK Location** を確認します。エラーに表示された「ebook2xtcが確認したSDK」と異なる場合は別のSDKへ導入した可能性があります。「SDK保存先を指定（認識しない場合）」からAndroid SDK Locationを選び、「準備を再確認」を押します |
| 「このPCではAVDの実行に使う仮想化を現在利用できません」 | 環境JSONの読み込みとAVD作成は続けられます。AVDを起動する前に「Windowsの機能を開く」で「Windows ハイパーバイザー プラットフォーム」を有効にし、**Windows PC本体を一度再起動**します（[2章](02-android-studio.md)） |
| 「Android SDKのCommand-line Tools（avdmanager）が見つかりません。」 | SDK Managerの「SDK Tools」で「Android SDK Command-line Tools (latest)」を入れます |
| 「Android Emulatorが見つかりません。…」 | SDK Managerで「Android Emulator」を入れ、ebook2xtcを起動し直します（[2章](02-android-studio.md)） |
| 「AVDを作成できません」「AVDの作成に失敗しました」（Javaに関する案内付き） | v0.2.3以降はAndroid Studio付属のJava 17以上を自動で探します。Android Studioのインストール先に `jbr\bin\java.exe` があるか確認してください。標準以外の場所に入れた場合は、その `jbr` フォルダーをユーザー環境変数 `JAVA_HOME` に設定し、ebook2xtcを再起動してから再試行します。`SKIP_JDK_VERSION_CHECK` で版の検査を回避しないでください。作りかけのAVDはアプリが片付けます |
| 「新しいAVD名は英数字、ドット、ハイフン、アンダースコアで指定してください。」 | 「その他」タブから任意JSONを手動で読み込む場合、AVD名に日本語や空白を使わないでください |
| 「環境プロファイルの読み込みは、キャプチャセッションと変換を終了してから行ってください。」 | 連続取得を停止して「キャプチャを終了」を押すか、変換が終わるのを待ってから読み込みます |
| 「Android環境の確認・AVDの作成が終わってから読み込んでください。」 | 起動直後の確認や、AVDの作成が終わるまで待ってから読み込みます |

## AVD環境を書き出す

1. 「取得」タブの③で、書き出すAVDを選びます。⓪出力対象と②キャプチャ解像度も、使う値に合わせておきます。
2. DPIを変えている場合は、そのAVDを起動したままにします。起動中のAVDの密度も記録されます。
3. 「その他」タブの「AVD環境を書き出す」を押します。
4. 保存先を選びます。既定のファイル名は `ebook2xtc-（AVD名）-environment.json` です。
5. 「環境を書き出しました」と表示されたら完了です。

ファイルに記録する内容は次のとおりです。

| 区分 | 内容 |
|---|---|
| AVD | Android API、システムイメージの識別子、AVDのハードウェア設定 |
| ebook2xtc | 出力対象、取得方式（常にADB直接取得）、キャプチャ倍率、（起動中なら）表示密度。旧版のJSONに「Windows画面取得」と書かれていても、ADB直接取得として読み込みます |
| リーダーアプリ導入情報 | 書き出し時に選んでいたリーダーアプリのパッケージ名（未選択なら空）、Google Playから導入する指定、書き出し元の導入状態と参考バージョン。AVD停止中や確認できないときは「未確認」として記録 |

リーダーアプリの本体・APKは書き出しません。アプリの版は参考情報で、移行先のPlayストアに同じ版がない場合もあります。Google／リーダーアプリのログイン情報、書籍、AVDのユーザーデータは含めません。

## 別のPCで読み込む

1. 読み込むPCに、Android Studio、Android Emulator、Android SDK Command-line Toolsを入れます（[2章](02-android-studio.md)）。AVDの作成に、Command-line Toolsの `avdmanager` を使います。
2. JSONの `system_image` に書かれたものと同じSystem Imageを、SDK Managerでインストールします。読み込むときに「未導入」と表示された場合は、表示された識別子に対応するSystem Imageを追加してから、やり直します。
3. キャプチャ中・変換中でないことを確かめます。作業フォルダーを作成・再開した後でも、「キャプチャを終了」していれば読み込めます。連続取得中は停止し、キャプチャを終了してから読み込んでください。起動直後のAndroid環境の確認中や、AVDの作成中も読み込めません。
4. 「その他」タブの「環境プロファイルを読み込む」を押し、JSONを選びます。
5. 新しいAVDの名前を入力します。同じ名前のAVDがある場合は、`（元の名前）_import2` のような重ならない名前が最初から入っています。
6. 「クリーンなAVDを作成しますか？」で内容を確かめ、「Yes」を押します。既存のAVDは上書きしません。作成には数十秒かかることがあり、その間はAndroid欄に「作成しています…」と表示され、AVDの操作は止まります。
7. 「環境を読み込みました」と表示されると、新しいAVDが③で選ばれ、出力対象・倍率・密度の値が反映されています。
8. 「取得」タブで「起動」を押します。起動完了後にリーダーアプリの導入状態を確認します。環境プロファイルから作ったAVDは、アプリを再起動した後も起動のたびに確認します。「その他」タブの「リーダーアプリ導入を確認」で、インストール後も再確認できます。古いJSONにはリーダーアプリ導入情報がなくても読み込めます。

新しいAVDを起動した後、次のことは利用者自身で行います（[3章](03-japanese-and-reader.md)、[4章](04-keyboard-and-sleep.md)）。

- Androidとリーダーアプリの日本語化
- Playストア／リーダーアプリのインストール
- Google／リーダーアプリのアカウントへのサインイン
- キーボード入力と画面スリープの設定

## アプリの設定を持ち運ぶ

アプリの取得・出力の設定（フォントテストのスナップ終了ページを含む）、密度の入力値、最後に選んだAVD、ウィンドウの配置、これまでに開いた作業フォルダーの一覧は、自動で `ebook2xtc.ini` に保存されます。「その他」タブの「アプリの配色」で選んだダークモード／通常モードも保存され、次回起動時に復元されます。切り替えはその場で画面全体に反映されます。 同じ「表示」欄の「アプリの文字サイズ」は小・中・大から選べます。小は従来のサイズで、初期値は中です。変更はすぐに反映され、次回起動時にも復元されます。AVD、リーダーアプリ、キャプチャ画像や出力の解像度には影響しません。文字を大きくして左ペインに収まらない場合は、左右のスクロールバーやペインの仕切りを使ってください。

`ebook2xtc.ini` は `ebook2xtc.exe` と同じフォルダーに保存されます。フォルダーごと移動すると、設定も引き継げます。フォルダーに書き込み権限が必要です。

ログイン情報や書籍データ、RAW画像は、INIに入りません。作業フォルダーとAVD自体は、それぞれ別に移してください。

## 新しい版に更新するとき

新しい版は、古い版とは別の場所に展開してください。古い `ebook2xtc` フォルダーに上書きして展開すると、新しい版で使わなくなったファイルが残り、起動に失敗することがあります。

1. 古い版の ebook2xtc を閉じます。
2. 新しい版のZIPを、古い版とは別のフォルダーに展開します。
3. 新しい版の `ebook2xtc.exe`（または `start_ebook2xtc.bat`）を起動します。
4. 「設定の引き継ぎ」が表示されたら「引き継ぐ…」を押し、古い版の `ebook2xtc` フォルダーにある `ebook2xtc.ini` を選びます。SDKの場所、AVD、リーダーアプリ、作業フォルダーの一覧、出力の設定などがそのまま使えます。初めて使う場合は「引き継がない」を押します。
5. 新しい版で、作業フォルダーを開けることと、AVDを起動できることを確かめます。
6. 問題がなければ、古い版のフォルダーを削除します。

「設定の引き継ぎ」は、新しい版のフォルダーに `ebook2xtc.ini` がないときの最初の起動で一度だけ表示されます。表示されなかった場合や「引き継がない」を選んだ場合は、新しい版を閉じてから、古い版の `ebook2xtc.ini` を新しい版のフォルダーへコピーして上書きしてください。

作業フォルダー（キャプチャ画像や書き出したファイル）と、AVD・リーダーアプリは、アプリのフォルダーの外にあるため、更新しても消えません。
