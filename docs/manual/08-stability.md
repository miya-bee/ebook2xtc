# 8. ページ安定判定の詳細

「取得」タブの「ページ安定判定（詳細設定）」は、ページを送った後、画面がいつ切り替わり、描画が落ち着いたかを判定する設定です。リーダーアプリのページめくりのアニメーションや、描画の途中の画面を保存しないために使います。

> 💡 **見出しのチェック欄は開閉用です**: 初期状態では項目が折りたたまれています。見出しのチェック欄で、項目を表示・非表示にできます。このチェック欄は詳細表示の開閉用で、ページ安定判定そのものを無効にするものではありません。折りたたんでいても、表示されている値が毎回の取得に使われます。

## 各項目の初期値と役割

| 項目 | 初期値 | 入力範囲 | 意味 |
| --- | ---: | ---: | --- |
| 最短待機 a 秒 | 0.5 | 0.0〜30.0秒 | ページ送りの直後に、判定を成功させてよい最短時間です |
| 最大待機 b 秒 | 3.0 | 0.1〜60.0秒 | 成功条件を満たすまで画面を確認する上限時間です。a以上に設定します |
| 検査周期 p 秒 | 0.20 | 0.01〜5.00秒 | 画面を取得して判定する間隔です |
| 次ページまでの待機 秒 | 1.4 | 0.5〜30.0秒 | RAWを保存してから次のページキーを送るまでの待機です。PCやリーダーアプリの描画が遅いときは長くします |
| 連続安定フレーム N | 3 | 2〜30 | 安定した画面が何回続けばよいかを指定します |
| 安定差分 ε | 0.005 | 0.000〜1.000 | 直前に検査した画面との差がこの値以下なら、1回分を安定と数えます |
| ページ変化 δ | 0.005 | 0.001〜1.000 | 保存済みの前ページとの差がこの値以上なら、新しいページに変わったと判定します |

εとδは、グレースケールにした画像どうしの平均絶対差を、0〜1に正規化した値です。小さい値ほど、差に敏感です。

- εを小さくすると、微細なちらつきも不安定とみなしやすくなります。大きくすると、小さな変動を許容しやすくなります。
- δを小さくすると、少しのページ差も検出しやすくなりますが、通知など一時的な変化もページ差と判定する可能性があります。逆にδが大きすぎると、短い章見出しなど、実際のページ差を検出できない場合があります。

## 判定のしくみ

1. 取得ごとに、a〜b秒の範囲から待機目標Tを無作為に選びます。Tの値は取得記録に残ります。
2. p秒ごとに画面を取得します。
3. T秒以上たったうえで、直近N回の画面差分がすべてε以下で、前ページとの差がδ以上なら、最後に確認した画面をRAWとして保存します。
4. b秒たっても条件を満たさなければ、RAWを保存せずに理由を表示します。

最初のページ（表紙）には比較する前ページがないので、ページ変化δの判定は行わず、待機時間と安定条件だけを確認します。

| 結果 | 条件 | ステータスの表示 | RAW |
|---|---|---|---|
| 成功 | 上の3を満たした | 「RAWを保存しました: …」 | 保存する |
| ページ変化なし | b秒までに前ページとの差がδに届かなかった | 「最大待機時間内に前ページからの変化を検出できなかったため、RAWは保存していません。」と、続けて「白紙・同一ページを意図している場合は『同一ページ／白紙も許容』を選んでください。」（下の注意を参照） | 保存しない |
| 画面が安定しない | ページ差は確認できたが、N回連続の安定条件を満たさなかった | 「最大待機時間内に画面が安定しなかったため、RAWは保存していません。」 | 保存しない |

> ⚠️ **「同一ページ／白紙も許容」の使い分け**: この案内は、前のページと同じ画面（同じ白紙が続く場合など）を意図して保存したいときのものです。中央がほぼ白の画面で止まった場合は、「同一ページ／白紙も許容」ではなく「白紙ページも許容（次の1ページだけ）」を使います（下の「例外のチェック」）。

連続取得では、ページ送りキーを送った後の「ページ変化なし」が3回に達すると、巻末、またはページ送りが反映されていない候補として停止します。キーを送らない再確認は試行履歴に残りますが、この3回には含みません（[7章](07-capture.md)）。

「次ページまでの待機」は、保存後、次のページ送りまでに最低限の間隔を空ける設定です。リーダーアプリの画面がまだ描画中なら、安定判定の方でも待機します。

## うまくいかないときの調整

| 症状 | 調整の考え方 |
| --- | --- |
| 表示が遅く、安定判定が時間切れになる | 最大待機 b を少し長くします |
| ページ送り後すぐに取得され、アニメーションが残る | 最短待機 a を長くするか、連続安定フレーム N を増やします |
| 画面の小さなちらつきで安定しない | εを少し大きくするか、bを長くします。文字や挿絵の動きまで許容しないよう、少しずつ調整してください |
| ページが変わっているのに「ページ変化なし」になる | AVD上のページが実際に変わったことを確認し、δを少し下げます |
| 取得に時間がかかりすぎる | aとbを短くします。PCが遅い場合は、先にpを長くして負荷を下げます |

最初は初期値を使い、ステータスの表示と右ペインのRAWを確認しながら、関係する値を一度に1つずつ調整してください。成功・失敗したときの判定値は、ページごとの取得記録とセッション台帳に保存されます。

## 例外のチェック

| チェック | 働き |
|---|---|
| 同一ページ／白紙も許容 | ページ変化δの確認だけを省きます。画面安定の待機・判定は、引き続き行います。同じページや白紙のページを意図して保存する場合だけオンにし、終わったらオフに戻してください |
| 全黒ページも許容（次の1ページだけ） | 中央がほぼ全黒の画像を止める安全確認を、次の1ページだけ省きます。本当に黒いページだと画面上で確認したときだけ使います。黒い画像を1枚保存すると、自動でオフに戻り、取得記録に許可したことが残ります。画面保護の回避は行いません |
| 白紙ページも許容（次の1ページだけ） | 中央がほぼ白の画像を止める安全確認を、次の1ページだけ省きます。リーダーアプリ上で白紙だと確認したときだけ使います。画面変化δの判定は省略せず、白紙を1枚保存すると自動でオフに戻ります |

連続取得中に画面中央がほぼ全黒またはほぼ全白になった場合、またはAndroidの画面上でリーダーアプリ以外のアプリ（通知や別のアプリなど）が表示された場合は、疑わしい画面をRAWに保存せず、次ページキーも送らずに確認待ちで停止します。表示中のアプリを確認できない場合も同様に止まります。この確認はAndroidの中の表示を見るもので、エミュレーターのウィンドウがWindows上で裏に隠れていても停止しません。これはリーダーアプリ内に表示された警告・確認画面をすべて自動判定するものではありません。再開前にリーダーアプリの表示内容とページ位置を目視で確認してください。

ほぼ全黒で止まったときは、詳細設定の枠が自動で開き、このチェックの場所が見えるようになります。本当に黒いページだと確認した場合だけ、次の1ページに限って許容できます。白紙ページは専用チェックで次の1ページだけ許可できます。「同一ページ／白紙も許容」は変化検出を省略する別の設定なので、白紙例外のために使わないでください。リーダーアプリ以外のアプリの停止は、どちらのチェックでも解除されません。
