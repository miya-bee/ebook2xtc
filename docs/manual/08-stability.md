# 8. ページ安定判定の詳細

「取得」タブの「ページ安定判定（詳細設定）」は、ページを送った後、画面がいつ切り替わり、描画が落ち着いたかを判定する設定です。リーダーアプリのページめくりのアニメーションや、描画の途中の画面を保存しないために使います。

> 💡 **見出しのチェック欄は開閉用です**: 初期状態では項目が折りたたまれています。見出しのチェック欄で、項目を表示・非表示にできます。このチェック欄は詳細表示の開閉用で、ページ安定判定そのものを無効にするものではありません。折りたたんでいても、表示されている値が毎回の取得に使われます。

## 各項目の初期値と役割

| 項目 | 初期値 | 入力範囲 | 意味 |
| --- | ---: | ---: | --- |
| 最短待機 a 秒 | 0.3 | 0.0〜30.0秒 | ページ送りの直後に、判定を成功させてよい最短時間です |
| 最大待機 b 秒 | 1.5 | 0.1〜60.0秒 | 成功条件を満たすまで画面を確認する上限時間です。a以上に設定します |
| 検査周期 p 秒 | 0.05 | 0.01〜5.00秒 | 画面を取得して判定する間隔です |
| 次ページまでの待機 秒 | 0.5 | 0.5〜30.0秒 | 表示が安定したと判定してから次のページキーを送るまでの待機です。RAWの保存はこの間に行います。PCやリーダーアプリの描画が遅いときは長くします |
| 連続安定フレーム N | 2 | 2〜30 | 安定した画面が何回続けばよいかを指定します |
| 安定差分 ε | 0.005 | 0.000〜1.000 | 直前に検査した画面との差がこの値以下なら、1回分を安定と数えます |
| ページ変化 δ | 0.005 | 0.001〜1.000 | 保存済みの前ページとの差がこの値以上なら、新しいページに変わったと判定します |

> ⏱️ **初期値の決め方**: 開発に使っているPC（CPU: AMD Ryzen 5 5500）で、Android 15のAVDを動かして測った値をもとにしています。このPCでは、画面1回の取得に0.3〜0.5秒かかります。楽天Koboはページを送ってから0.65〜0.97秒で次のページを描き終え、Kindleは最初の確認の時点で描き終えています。描き終えたページは直前の画面との差がちょうど0で、めくっている途中の画面は0.04以上違うため、変化の後に同じ画面が2回続けば描き終わっています。画面1回の取得に0.3〜0.5秒かかるので、検査周期pは短くしても判定は変わりません。楽天Koboの30ページで、以前の初期値（a 0.5・b 3.0・p 0.2・N 3・待機1.4秒）は1ページ3.97秒、この初期値では2.16秒で、取りこぼしはありませんでした。以前の版の設定ファイルで「次ページまでの待機」が1.4秒のままなら、0.5秒に直します（自分で変えた値はそのままです）。

εとδは、グレースケールにした画像どうしの平均絶対差を、0〜1に正規化した値です。小さい値ほど、差に敏感です。

- εを小さくすると、微細なちらつきも不安定とみなしやすくなります。大きくすると、小さな変動を許容しやすくなります。
- δを小さくすると、少しのページ差も検出しやすくなりますが、通知など一時的な変化もページ差と判定する可能性があります。逆にδが大きすぎると、短い章見出しなど、実際のページ差を検出できない場合があります。
- 文字のあるページと文字のない白紙のページは、δにかかわらず、ページが変わったと判定します。1行だけのページ（章末など）と白紙のページの差は、δよりずっと小さいためです。文字があるかどうかは、白一色の判定（下の「例外」）と同じく、上下の端（画面の高さの8%ずつ）と左右の端（2%ずつ）を除いて見ます。

## 判定のしくみ

1. 取得ごとに、a〜b秒の範囲から待機目標Tを無作為に選びます。Tの値は取得記録に残ります。
2. p秒ごとに画面を取得します。
3. T秒以上たったうえで（ページを送ってから最初に画面を取得するまでの時間も、Tに含みます）、直近N回の画面差分がすべてε以下で、前ページとの差がδ以上（または、前ページと文字のあるなしが違う）なら、最後に確認した画面をRAWとして保存します。
4. b秒たっても条件を満たさなければ、RAWを保存せずに理由を表示します。ただし、b秒までに画面をまだN回取得できていないときは、N回取得するまで待ってから判定します。
5. それでも、「bの3倍」と「10秒」の長いほうを過ぎたら、N回に届かなくても判定を終えます。

> 🐢 **遅いPCでの待機**: 画面1回の取得にかかる時間は、PCの性能でほぼ決まります。特に表紙と2ページ目は、1回の取得に1秒前後かかることがあります。上の4.により、取得の遅いPCでも、画面を確かめる回数が足りないまま「画面が安定しない」と判定されることはありません。1回の取得にかかった時間は、取得記録の `sample_interval_seconds` に残ります。b秒を過ぎて待った場合は、`waited_past_b_for_frames` が `true` になります。

最初のページ（表紙）には比較する前ページがないので、ページ変化δの判定は行わず、待機時間と安定条件だけを確認します。

| 結果 | 条件 | ステータスの表示 | RAW |
|---|---|---|---|
| 成功 | 上の3を満たした | 「RAWを保存しました: …」 | 保存する |
| ページ変化なし | b秒までに前ページとの差がδに届かなかった | 「最大待機時間内に前ページからの変化を検出できなかったため、RAWは保存していません。」と、続けて「白紙・同一ページを意図している場合は『同一ページ／白紙も許容』を選んでください。」（下の注意を参照） | 保存しない |
| 画面が安定しない | ページ差は確認できたが、N回連続の安定条件を満たさなかった | 「最大待機時間内に画面が安定しなかったため、RAWは保存していません。」 | 保存しない |

> ⚠️ **「同一ページ／白紙も許容」の使い分け**: この案内は、前のページと同じ画面（同じ白紙が続く場合など）を意図して保存したいときのものです。文字のない白一色の画面で止まった場合は、「同一ページ／白紙も許容」ではなく「白紙ページも許容（次の1ページだけ）」を使います（下の「例外のチェック」）。

⑨の直後、表紙の取得で「画面が安定しない」になったときは、何も保存せず、ページも送っていません。OKを押すと⑨を押せる状態に戻るので、リーダーアプリに表紙が表示されたままであることを確認して、もう一度⑨を押します。⑥・⑦からやり直す必要はありません。2ページ目以降で止まったときは、「保存済みページの続きから連続取得」で再開します。

連続取得では、ページ送りキーを送った後の「ページ変化なし」が3回に達すると、巻末、またはページ送りが反映されていない候補として停止します。キーを送らない再確認は試行履歴に残りますが、この3回には含みません（[7章](07-capture.md)）。

「次ページまでの待機」は、表示が安定してから次のページ送りまでに、最低限の間隔を空ける設定です。RAWの保存とリーダーアプリの確認はこの待機の間に行うので、保存に時間がかかっても、その分ページ送りが遅れることはありません（保存が待機より長くかかったときは、保存が終わりしだい送ります）。リーダーアプリの画面がまだ描画中なら、安定判定の方でも待機します。

## うまくいかないときの調整

調整して分からなくなったときは、「ページ安定判定（詳細設定）」の一番下にある「既定値に戻す」を押します。a・b・p・次ページまでの待機・N・ε・δが既定値（0.3秒・1.5秒・0.05秒・0.5秒・2・0.005・0.005）に戻り、例外のチェックはすべて外れます。

| 症状 | 調整の考え方 |
| --- | --- |
| 表示が遅く、安定判定が時間切れになる | 最大待機 b を少し長くします（2.0〜3.0秒。以前の初期値は3.0秒） |
| ページ送り後すぐに取得され、アニメーションが残る | 最短待機 a を長くするか、連続安定フレーム N を増やします |
| 画面の小さなちらつきで安定しない | εを少し大きくするか、bを長くします。文字や挿絵の動きまで許容しないよう、少しずつ調整してください |
| ページが変わっているのに「ページ変化なし」になる | AVD上のページが実際に変わったことを確認し、δを少し下げます |
| 取得に時間がかかりすぎる | 初期値より長くしている値を、初期値へ戻します。PCが遅い場合は、先にpを長くして負荷を下げます |

### 非力なPCで使うとき

初期値は、開発PC（Ryzen 5 5500）で余裕をもって動く値です。これより遅いPCや、AVDと一緒にほかの重いアプリを動かしているPCでは、止まったときの表示に合わせて、次の順に値を延ばします（初期値から下げる＝待ち時間を短くする方向ではなく、待ち時間を長くする方向です）。表の右端は、以前の版の初期値で、もっとも慎重な値です。

PCの速さは、作業フォルダーの `session.json` に残る、ページごとの `sample_interval_seconds`（画面1回の取得にかかった秒数）で分かります。開発PCでは0.3〜0.5秒です。0.8秒を超えるPCでは、はじめから下の「目安」の値にしておくと安心です。

| 症状 | 延ばす項目 | 目安 | もっとも慎重な値 |
| --- | --- | ---: | ---: |
| 「最大待機時間内に前ページからの変化を検出できなかった」（ページ変化なし）で、本の途中なのに止まる | 最大待機 b | 2.0〜2.5秒 | 3.0秒 |
| 「最大待機時間内に画面が安定しなかった」で止まる | 最大待機 b | 2.0〜2.5秒 | 3.0秒 |
| ページをめくっている途中の画面が保存された | 連続安定フレーム N | 3 | 3 |
| ページ送りが効かないことがある、ページが飛ぶ | 次ページまでの待機 | 0.8〜1.0秒 | 1.4秒 |
| 取得中にPC全体が重くなる、AVDの動きが極端に遅い | 検査周期 p | 0.1〜0.2秒 | 0.2秒 |
| 上のどれでもないが、念のため慎重にしたい | 最短待機 a | 0.5秒 | 0.5秒 |

- 一度に1つずつ変え、数十ページ取得して止まらなくなったら、そこで止めます。全部を「もっとも慎重な値」にすると、以前の版と同じく1ページ4秒前後かかります。
- εとδは、PCの速さとは関係がないので変えません。
- 速いPCでも、aとbをこれより下げても、ほとんど速くなりません。ページを送ってから描き終わるまで（楽天Koboで約0.8秒）は、どうしても待つためです。

最初は初期値を使い、ステータスの表示と右ペインのRAWを確認しながら、関係する値を一度に1つずつ調整してください。成功・失敗したときの判定値は、ページごとの取得記録とセッション台帳に保存されます。

## 例外のチェック

| チェック | 働き |
|---|---|
| 同一ページ／白紙も許容 | ページ変化δの確認だけを省きます。画面安定の待機・判定は、引き続き行います。同じページや白紙のページを意図して保存する場合だけオンにし、終わったらオフに戻してください |
| 全黒ページも許容（次の1ページだけ） | 中央がほぼ全黒の画像を止める安全確認を、次の1ページだけ省きます。本当に黒いページだと画面上で確認したときだけ使います。黒い画像を1枚保存すると、自動でオフに戻り、取得記録に許可したことが残ります。画面保護の回避は行いません |
| 白紙ページも許容（次の1ページだけ） | 文字のない白一色の画像を止める安全確認を、次の1ページだけ省きます。リーダーアプリ上で白紙だと確認したときだけ使います。画面変化δの判定は省略せず、白紙を1枚保存すると自動でオフに戻ります |

連続取得中に画面中央がほぼ全黒になった場合や、文字のない白一色の画面になった場合、またはAndroidの画面上でリーダーアプリ以外のアプリ（通知や別のアプリなど）が表示された場合は、疑わしい画面をRAWに保存せず、次ページキーも送らずに確認待ちで停止します。表示中のアプリを確認できない場合も同様に止まります。この確認はAndroidの中の表示を見るもので、エミュレーターのウィンドウがWindows上で裏に隠れていても停止しません。これはリーダーアプリ内に表示された警告・確認画面をすべて自動判定するものではありません。再開前にリーダーアプリの表示内容とページ位置を目視で確認してください。

ほぼ全黒で止まったときは、詳細設定の枠が自動で開き、このチェックの場所が見えるようになります。本当に黒いページだと確認した場合だけ、次の1ページに限って許容できます。白紙ページは専用チェックで次の1ページだけ許可できます。「同一ページ／白紙も許容」は変化検出を省略する別の設定なので、白紙例外のために使わないでください。リーダーアプリ以外のアプリの停止は、どちらのチェックでも解除されません。
